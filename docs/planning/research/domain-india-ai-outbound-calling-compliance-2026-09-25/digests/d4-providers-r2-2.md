## Claims

1. **Claude in Amazon Bedrock (Opus 4.7 and later, "bedrock-mantle" Messages API): the region table lists `ap-south-1` (Mumbai) and `ap-south-2` (Hyderabad) as "Global" endpoint type only.** There is no regional, In-region-only or geography (US/EU/JP/AU) option for India. Geography inference profiles exist only for US, EU, JP and AU.
   Source: https://platform.claude.com/docs/en/build-with-claude/claude-in-amazon-bedrock. Publisher: Anthropic (Claude Platform Docs). pub/last-updated: not shown on the page. The page lists models up to Claude Opus 5.5 / Fable 5.1, so it is current as of 2026-09. Confidence: high. Class: gatekeeper-policy. Two-source: YES. The AWS blog of 2026-08-27 (claim 3) names only OpenAI models for the India profile, and the round-1 AWS blog (2026-03) describes Global CRIS for Claude in India. Round-1 hypothesis "Claude only via Global CRIS in ap-south-1": **CONFIRMED** (still true as of 2026-09).
2. **The same Anthropic page says Regional endpoints "resolve to the single AWS region you specify, for data-residency requirements" at a 10% pricing premium, and that Global endpoints use "dynamic routing across all available regions".** So a Claude call from Mumbai may be processed in any commercial AWS region.
   Source: same as claim 1. Confidence: high. Class: gatekeeper-policy. Two-source: YES. AWS docs say Global CRIS "destination Regions ... include all commercial Regions" (https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html, AWS, undated, accessed 2026-09-25).
3. **AWS offers an India geographic cross-region inference profile only for OpenAI GPT-5.6 Terra and Luna (`in.openai.gpt-5.6-terra`, `in.openai.gpt-5.6-luna`).** Requests "route only between ap-south-1 and ap-south-2", and "the India geographic profile keeps inference within India". The post does not mention Claude or any other model family.
   Source: https://aws.amazon.com/blogs/machine-learning/introducing-openai-models-on-amazon-bedrock-for-in-country-inferencing-in-india/. Publisher: AWS ML Blog. pub_date: 2026-08-27. Confidence: high. Class: gatekeeper-policy. Two-source: SINGLE-SOURCE for the "in." profile's existence and scope; the AWS inference-profile docs now point to per-model cards, which were not fetched. Round-1 hypothesis "OpenAI GPT-5.6 has India-geography profiles": **STILL SINGLE-SOURCE** (same upstream, re-verified).
4. **Geography-tied Bedrock profiles (such as US, EU, APAC) have fixed destination lists that "will never change", while Global profiles can gain destination regions over time.** Opt-in destination regions may store "input prompts and output results ... for abuse detection purposes".
   Source: https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html. Publisher: AWS Docs. last-updated: not shown. Confidence: high. Class: gatekeeper-policy. Two-source: SINGLE-SOURCE.
5. **The AWS India blog states "Amazon Bedrock uses a zero data retention (ZDR) data security model ... by default, Amazon Bedrock does not store model inputs or outputs".** The Bedrock data-protection page states that model providers "don't have access to Amazon Bedrock logs or to customer prompts and completions" (Model Deployment Accounts are operated by AWS).
   Sources: the AWS blog (2026-08-27), and https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html (AWS, undated). Anthropic's page adds "zero operator access (Anthropic personnel have no access to the inference infrastructure)". Confidence: high. Class: gatekeeper-policy. Two-source: YES for no storage / no provider access. An explicit "no training on customer data" sentence was NOT found in the pages fetched this run (see Looked for, not found).
6. **In Microsoft Foundry, Data Zone types process data "anywhere within the Microsoft-specified data zone (US, EU, or Asia Pacific (APAC))", and for Data Zone Standard the APAC zone means "data processed within any Asia Pacific nation".** No India data zone is listed.
   Source: https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-sold-directly-by-azure-region-availability. Publisher: Microsoft Learn. ms.date 2026-09-03, updated 2026-09-04. Confidence: high. Class: gatekeeper-policy. Two-source: PARTIAL. The data-privacy page (claim 9) confirms the Data Zone semantics but names only the US and EU examples. The Data Zone Provisioned and Batch sections on the same page still say "US or EU" only, which is inconsistent within the page (see Leads).
7. **For `southindia`, the Standard/Regional deployment type (processing stays in the deployment region) lists only gpt-4.1-mini (2025-04-14), gpt-4o (2024-11-20), text-embedding-3-large, text-embedding-ada-002 and whisper.** Global Standard in southindia lists a wide set that includes gpt-5.x, gpt-6-_, gpt-realtime-2.x and gpt-4o-transcribe. Data Zone Standard lists gpt-5.2, gpt-5.3-codex, gpt-5.4, gpt-5.4-mini, gpt-5.6-sol and model-router. Regional Provisioned lists gpt-4.1, gpt-4o, gpt-5, gpt-5-mini, gpt-5.1, gpt-5.4-mini and o3-mini.

## Leads

1. **CONTRADICTION (Azure page, internal):** Data Zone Standard says zones are US, EU or APAC, but the Data Zone Provisioned and Data Zone Batch sections on the same 2026-09-03 page still say "US or EU" only, and the data-privacy page (2026-05-18) gives only US and EU examples. Also note that an APAC data zone is multi-country, not India-only. A human-readable confirmation of APAC Data Zone membership (is India inside it?) is needed.
2. **CONTRADICTION (framing, search answer vs primary):** the search-engine summary for the Bedrock query attributed the "India geographic profile" to Claude. The primary AWS blog (2026-08-27) scopes it to OpenAI GPT-5.6 only, and Anthropic's region table shows Mumbai and Hyderabad as Global only. The primary sources are preferred, and the aggregator conflation is discarded.
3. The Azure `centralindia` column was absent from the fetched region-availability pivot. The page's other pivots (tabs by geography) may list Central India, so re-fetch with the region pivot or query the Azure models API.
4. Azure realtime voice models (gpt-realtime-2.x, gpt-4o-transcribe) are Global-only in southindia. This is material for a voice-call product: speech processing may leave India unless Standard/Regional voice models are used.
5. For Bedrock, re-check the per-model "Regional availability" tables on the model cards (AWS now points there) for Claude and other families (Amazon Nova, Meta Llama, Mistral) in ap-south-1 In-Region. Only Claude and OpenAI were resolved this run.
6. Anthropic's page offers "Claude Platform on AWS" (Anthropic-operated, Marketplace billing). Its data-location terms are unknown and should be checked before assuming Bedrock-equivalent residency.
7. The Vertex data-residency page needs a direct read (the fetch returned a nav shell). Priorities are current Gemini generations in asia-south1/asia-south2, the context-caching and grounding exceptions, and the abuse-logging opt-out.
8. Razorpay: fetch the core Payment Gateway privacy policy / merchant DPA and the "Product Annex" localisation commitments. The RBI payment-data storage circular (2018) remains the regulatory anchor, but it was not retrieved this run.
