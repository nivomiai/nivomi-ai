# Technical debt and known constraints

| Item                                         | Impact                                                                                                     | Resolution                                                                   |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Local Node is 22.12                          | ESLint pinned to 9 (end of life upstream); some dev tools warn on engine; Nest CLI unusable                | Upgrade to Node 24 LTS, update `.nvmrc`, then move to ESLint 10              |
| TypeScript held at 6.0                       | Cannot adopt TypeScript 7 (native compiler)                                                                | Upgrade when typescript-eslint supports it                                   |
| No CSP on the web app                        | Weaker XSS defense in depth                                                                                | Nonce-based CSP via Next.js proxy when the app gains real pages              |
| No deploy stage in CI                        | Nothing is deployed                                                                                        | After the hosting decision                                                   |
| `uv` not installed                           | BMAD skills that shell out via `uv run` need the `python` fallback; `bmad-build(-auto)` halt on activation | Install uv (`winget install astral-sh.uv` or `pip install uv`)               |
| Placeholder git author on initial commits    | Bootstrap commits are authored `Your Name <you@example.com>`                                               | Set a real identity; optionally rewrite before the first push                |
| Web design system is only the brand seed     | Product app UI would diverge without components/patterns beyond the website tokens                         | BMAD UX phase, building on `apps/web/app/globals.css` tokens                 |
| Website legal pages are placeholders         | `/privacy` and `/terms` cannot be published as final                                                       | Counsel-approved text before production launch                               |
| Website lead form has no backend             | Enquiries go only via WhatsApp/email handoff; nothing is stored or tracked server-side                     | Add an API `LeadCaptureClient` once the database exists                      |
| No analytics provider on the website         | `track()` events are no-ops                                                                                | Choose a provider (privacy-reviewed) and register a sink                     |
| Rate-limit store is in memory                | Limits are per process; running more than one API task multiplies them                                     | `RedisRateLimitStore` (ElastiCache) before scaling past one task (ADR-019)   |
| No MFA yet                                   | Owner/admin/Super Admin accounts are protected by password only (PRD FR-5 requires MFA)                    | TOTP enrolment and step-up in the auth hardening phase (ADR-018)             |
| `AuthService` combines identity and sessions | One large service; harder to evolve MFA/Super Admin identity separately                                    | Split into `IdentityService` and `SessionService` with the MFA work          |
| No SES / MSG91 adapters                      | Production cannot start (`EMAIL_PROVIDER=ses` fails fast); OTP not available                               | Implement from official AWS SES and MSG91 docs once accounts exist (ADR-015) |
| Tests run on PGlite only                     | Cross-connection behaviour (`SKIP LOCKED` between workers, pool exhaustion) is not exercised               | CI job with a real PostgreSQL 17/18 service container                        |
| drizzle-kit pulls an old esbuild (dev only)  | `npm audit` reports 4 moderate dev-only advisories (GHSA-67mh-4wv8-2f99); not in the production tree       | Upgrade drizzle-kit when a release drops `@esbuild-kit`                      |
| Super Admin has no UI or API                 | `users.is_super_admin` exists but no control plane; organization approval is manual in the DB              | Super Admin phase (PRD §6 control plane)                                     |
| No `Idempotency-Key` handling                | Retried side-effecting POSTs rely on natural uniqueness only                                               | Add with the first money- or call-moving endpoints                           |
| Invitation lists are capped, not paged       | Very large teams (>500 members / >200 open invites) are truncated                                          | Keyset pagination like the audit log when needed                             |
